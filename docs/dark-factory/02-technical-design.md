# 02 — Technical Design: Tartarus Arena

Source of truth for semantics: `01-game-design.md` (VR-xx, GS-xx). Nothing here re-decides a number.

## ADR-1 Engine and language [C]
UE 5.8, C++ module `ParagonArena` + Gameplay Ability System. Single-player standalone first [C]; GAS
components keep their default replication settings (free), but nothing is built or tested for network
play in v1.

## ADR-2 Code-first, data in text (token + reliability budget)
Editor assets are created only where UE requires them (maps, the Paragon content itself). Everything
else is C++ or text data the agent can diff:
- Heroes and abilities: `Content/Data/heroes.json` (authority for kits and numbers), parsed with
  `FJsonObjectConverter` into `FHeroDef` / `FAbilityDef` structs; asset references are soft object
  paths into the Paragon packs.
- Input: `UInputAction` / `UInputMappingContext` created at runtime in C++ (no input assets).
- Gameplay effects (damage, cost, cooldown, stun, slow, shield, heal): `UGameplayEffect` subclasses
  configured in C++ constructors; magnitudes via SetByCaller from the JSON numbers.
- Ability animations: the hero's Paragon `UAnimSequence`s played with `PlaySlotAnimationAsDynamicMontage`
  (DefaultSlot) — fallback if a pack's AnimBP lacks the slot: montages generated by a Python script.
- FX: the pack's particle systems spawned by path; `UParticleSystem` (Cascade) or `UNiagaraSystem`
  handled by one helper (`ArenaFx::Spawn`).
- HUD: `AArenaHUD` Canvas drawing (health bars, cooldowns, tickets, kill feed, damage numbers).
- Arena map: built by `Tools/build_arena.py` (Python Editor Script Plugin) from Agora/Monolith pieces or
  a cut of the pack's own level; adds team bases, portals, PlayerStarts, NavMeshBoundsVolume.

## Per-tick flow and transforms
Input → `AArenaHero` (move, aim ray from camera) → ability activation (`CanActivate`: cooldown/mana,
VR-02, pure check) → cast: montage + FX (presentation) → hit query (sweep/overlap/projectile) →
`TargetFilter::IsHostile` (VR-04) → `HitRegistry::FirstHit` (VR-03) → damage GE (ArenaMath, VR-01) →
AttributeSet clamp → on death: GameMode `TicketLedger.Apply(kill)` (VR-05) → respawn timer (VR-06).
All transforms are `pure` or in-memory state changes; the only `effect` is writing user settings
(idempotent overwrite, compensation = defaults).

## Observability surface
- Log category `LogArena`, one line per event: `ARENA t=<s> scn=<GS-id|match> evt=<spawn|cast|hit|death|ticket|respawn|wave|victory> ...`.
- Console command `Arena.Status` → one line `ARENA_STATUS tickets=A/B alive=.. fps=..`.
- Headless bot match: `UnrealEditor-Cmd <uproject> /Game/Maps/Arena_P -game -nullrhi -ExecCmds="Arena.BotMatch seed=N minutes=3" -log`
  → summary line `ARENA_SUMMARY seed=N casts=.. stuck=.. errors=..` + `PASS/FAIL` lines.
- Screenshots: `HighResShot` into `Saved/Screenshots`, copied to `Captures/` as evidence.

## ADR-3 Reactions and physics (2026-09-27)
Replaces the ticket ledger with `ArenaCore::FScoreLedger` (points + limit + clock winner) and the ragdoll death.
- Slots: every Paragon anim blueprint has one slot node, `UpperBody` (read by reflection from its `AnimNode_Slot`
  properties, `AArenaCharacter::AnimSlot`); the mannequin one has `DefaultSlot`. Sequences are wrapped in dynamic
  montages on that slot. Death, drop-in and victory bypass the anim blueprint (`PlayAnimation`, single node) so the
  whole body plays and the last frame holds; the blueprint is restored after the drop-in.
- Additive hit reactions cannot play in a full-pose slot: `Tools/make_hitreacts.py` makes regular copies under
  `/Game/Arena/Generated/Anims` (derived from Epic content, gitignored, cooked via the manifest).
- Floors: `UArenaMovementComponent::IsWalkable` rejects pawns and simulating bodies; `SlideOffCharacters` only
  adds horizontal velocity. No code path launches a unit upward except abilities (capped in data, VR-13) and
  hero-only jump pads.
- Props: `ArenaPhysics::CalmProp` (damping, spin cap, depenetration 60 cm/s), `RadialImpulse` capped at 650 cm/s,
  a `UBoxComponent` dynamic nav obstacle riding on each prop; character push tuned in `-ArenaAnimLab`.
- Navigation: one supported agent of 42 cm for the 40 cm hero capsule; spawns search a free spot
  (`AArenaGameMode::FreeSpot`); retreat goals are per-hero spots on a ring (`FSnapshot::BaseSlot`).
- Evidence harness: `Game/ArenaAnimLab.cpp` (`-ArenaAnimLab`), measured checks + screenshots; see 07-qa.

## ADR-4 Targeting, combat rules, terrain (2026-09-27)
- Indicators: `AArenaIndicator` (three deferred decals using `M_ArenaIndicator`, one custom HLSL node for disc, ring,
  lane and cone; decal UV U = aim direction). The shapes come from shared helpers in `ArenaAbilityHelpers`
  (`GroundTarget`, `ProjectileReach`, `LowestAlly`, `AArenaCharacter::DashDestination`), the same the abilities use,
  so the preview is the outcome (VR-15). The player controller aims (1-4), casts (LMB / same key) or cancels (RMB, Esc).
- Hits: `DamageInRadius` counts the target's capsule edge, widens cones by the target's width, keeps one level
  (vertical window) and needs line of sight against WorldStatic (VR-16).
- Dash: `FRootMotionSource_MoveToForce` towards the navmesh-raycast end point; ends by its clock.
- Melee bots: `ArenaBot::MeleeContactCm` (115), swing gate at +35 cm, contact moves without the overlap bonus; RVO
  avoidance only within a team.
- Props: `UArenaMovementComponent::ApplyImpactPhysicsForces` sets the prop's ground velocity to the walker's pace.
- Terrain: collision boxes rendered with `M_ArenaCliff` (WorldAlignedTexture), thick ramps, sloped parapets.
- Evidence harnesses: `Game/ArenaMechLab.cpp` (`-ArenaMechLab`, `-ArenaCamShots`); see 08-qa.

## ADR-5 Aim assistance and hit confirmation (2026-09-27)
- Who: `AArenaCharacter::bAssistedAim` is set by `AArenaPlayerController::OnPossess` and cleared on unpossess, so
  only the human's hero is assisted; bots and lab units never are. CVar `arena.AimAssist` (default 1).
- Pick: every `PlayerTick` `ArenaAbilityHelpers::FindAimTarget` (camera ray; basic or aimed ability) →
  `AimTarget`. Melee: reach + 40 cm, 65°, score = angle + distance. Single projectile: body within 60 cm + 3.5 % of
  the distance of the ray, heroes before minions. Line of sight required.
- Use: `UArenaAbility::ActivateAbility` passes the target to `Execute`. A shot aims at `LeadPoint` (chest +
  horizontal velocity × flight time, two iterations), again when it leaves, flies straight (no lob) and has a 40 cm
  hit sphere (bots 26 cm). A swing holds the body on the target (`HoldFacing` overrides `FaceRotation` for the
  wind-up), re-aims at the target in `Execute` and `Lunge`s (root-motion move-to, stops dead) over a gap ≤ 70 cm.
  The indicator's lane / cone uses the same `LeadPoint`.
- Confirm: `ReceiveDamage` with a player source → `AArenaHUD::NotifyPlayerHit` (X marker white / yellow / red,
  bracket and bar flash, counter `HitMarkersShown`), `ArenaHitSound::Play` (synthesized PCM tick through
  `USoundWaveProcedural`, the packs have no impact sounds), overlay material `M_ArenaHitFlash` (unlit translucent
  rim, 0.18 s) on the victim; `FlashSwing` draws the swing's arc on the ground (grey when it whiffs). The overlay is
  kept to the player's hits and the player's own hero: set per hit, it recreates the mesh's render state, and in a
  full bot fight that cost 20 FPS.
- Evidence harness: `Game/ArenaAimLab.cpp` (`-ArenaAimLab`), the real player controller drives the camera; see 09-qa.

## ADR-6 Ranks, levels, item tree, predictable effects (2026-09-27)
- Authority: `heroes.json` — hero growth per level and `skillOrder`; per ability `icon`, `desc`, `width` and the
  `…PerRank` growth; items with `tier`, `from` (recipe), `critChance`, `armorPen`, `passive` + `passiveA/B/Cd/Text`;
  rules `maxLevel`, `xpBase`, `xpGrowth`, `xpPerSecond`, `xpMinion`, `xpShareRadius`, `xpHeroKill(PerLevel)`, `xpAssist`.
  `ArenaTypes.cpp` rejects recipes with missing or not-lower-tier parts and rank-5 values out of range.
- Pure rules (`ArenaCore`, specs `Arena.Core.Levels…`, `Arena.Core.Item recipes`): `XpToNext / XpForLevel /
  LevelForXp`, `MaxRankAt`, `FreePoints`, `CanRankUp`, `Ranked`, `NextCrit` (deterministic), `TotalCost`,
  `BuyPrice` (recursive: owned parts and parts of parts are used up), `SellValue`, `CanBuy` (consumed parts free
  slots), `KnockDistanceCm / KnockHeightCm / KnockAirSeconds`.
- `AArenaCharacter::Ability(Slot)` returns the ability at its rank (the basic attack at the level); every cast, the
  indicator, the tooltip and the bot's readiness read it. `Ranks[5]` survive a death (`FArenaRespawn`).
- Item passives: `FItemPassives` built in `SetItems` (unique per passive id); applied in
  `ArenaAbilityHelpers::ApplyHitEffects` (archon, on-hit, spell blade, execute, crit, echo, lifesteal) and
  `ReceiveHit` (thorns, last stand), `ReceiveHeal` (overheal) and `Tick` (regeneration). `FArenaHit` carries basic /
  crit / penetration / reflect flags.
- Displacement: `Displace` = `FRootMotionSource_JumpForce` (knock-up) or `MoveToForce` to the navmesh-limited end
  (knockback); the unit is airborne (no casting) for the planned time (+ a hit-stop).
- Timing: a ground area is spawned at the cast and detonates after its Delay; `AArenaIndicator::Telegraph` drives
  the material's `Fill` from 0 to 1 over that Delay. A basic attack's ability ends after its Delay, so its cooldown
  (attack speed) sets the attack rate, not its animation.
- Icons: game-icons.net PNGs (CC BY 3.0, `CREDITS.md`) in `Tools/Icons`, imported by `Tools/import_icons.py` into
  `/Game/Arena/Icons/T_Icon_*` (UI, 128 px); the HUD tints them over the hero's pose capture.
- Evidence harness: `Game/ArenaSkillLab.cpp` (`-ArenaSkillLab`); see 10-qa.

## ADR-7 Death fade, pose blending, turning, camera, own environment meshes (2026-09-27)
- Death: `AArenaCharacter::Die` → a hero's fall runs in `UArenaPoseBlendInstance` (a native anim instance that
  samples the sequence and blends from a pose snapshot over 0.18 s; a pending play hands the snapshot to the new
  instance before its first evaluation, no reference-pose frame); a minion's stagger is a montage on its full-body
  slot, then `StartRagdoll` (physics asset, WorldStatic only, depenetration 60 cm/s). `FadeAt`/`FadeLen` drive the
  scalar `ArenaFade` 0→1 (smoothstep) on the tint MIDs; translucent slots are hidden when it starts.
- Fade materials: `Tools/make_fade_materials.py` (run with `-culture=en`: pin names are localized) writes masked
  copies `/Game/Arena/Generated/Fade/F_<pack>_<name>`: opacity mask × screen-space dither of (1 − ArenaFade),
  material-attribute graphs through Break/Make Material Attributes on the output the material used. Authority: the
  pack materials; the copies are derived and gitignored. Paragon's own `FadeOut` darkens to black: not used.
- Turning: `UseSmoothTurning(true)` for AI (controller desired rotation, 720°/s heroes, 540°/s minions); the player's
  hero keeps controller yaw (aim). Metric: `AArenaCharacter::YawSnaps` → `ARENA_SUMMARY yaw_snaps`.
- Camera: `UArenaSpringArm` (in at once, out at 5/s), lag 14 with substepping and 130 cm cap, no rotation lag,
  Perlin shake, +6° FOV while dashing.
- Environment: `Tools/Blender/rock_skirts.py` (Blender 5.2, seeded convex-hull rocks) → `Tools/Blender/out/*.fbx` →
  `Tools/import_env_meshes.py` (orientation gate: UE mirrors Blender Y) → `build_arena.py build_skirts` at the outer
  feet of the ramp parapets, visual only, own random generator (the jungle keeps its layout).

## ADR-8 Crisp HUD, indicator look, ability effects placement (2026-09-27)
- HUD text: `AArenaHUD::Text/Measure` draw `/Engine/EngineFonts/Roboto` through `FSlateFontInfo` at the pixel size
  (legacy size x scale, min 12 px at 1080p, bold from 15 px, 1-2 px outline); `/Engine/EngineFonts` is always cooked.
- Icons 256 px + mips (`Tools/import_icons.py`); portraits 512 px RT with mips and an unlit backdrop `M_ArenaBackdrop`.
- Indicators: `M_ArenaIndicator` custom node returns (fill, rim, outline); opacity, base colour and emissive are built
  from them; C++ passes `Edge` (24 cm) and `Aspect` (lane far end).
- Abilities: `FArenaAbilityDef::FxScale` (0 = from the radius, capped); `ArenaFx::AttachFor` (buff FX on the bearer
  for its duration, telegraph FX on the area actor); `AArenaCharacter::ShowAura` (decal ring); explosive projectiles
  burst before recording the hit; `AArenaProjectile::LobTo` solves the arc to `ArenaAbilityHelpers::LobLanding`.
- Verification: `-ArenaFxLab` (LabMode 7).

## ADR-9 Front end, settings, training centre (2026-09-27, v10)
- Menus are drawn by the canvas HUD like the rest (no widget assets): `EArenaMenu` on the player controller, buttons
  register their rectangles per frame (`AArenaHUD::HitArea` → `MenuHitAt`), `MenuAction(Action, Arg)` does the work.
- Settings: `FArenaSettings` — graphics in `UGameUserSettings`, the rest in `[ArenaSettings]` of GameUserSettings.ini;
  applied at once.
- Training: `/Game/Maps/Training` (built by `Tools/build_training.py` from engine shapes), recognised by name;
  `OpenLevel("Training", "Hero=N")`; dummies are `TargetPoint`s tagged Dummy / Mover.

## ADR-10 Cast modes, relative colours, Paragon minions, SM6 + Lumen (2026-09-28, v11)
- Casting: `AArenaPlayerController::PressAbility / ReleaseAbility`; `FArenaSettings::CastMode` 0 quick (aim while held,
  release casts), 1 instant, 2 confirm; `NotReadyReason` decides deny vs buffer; the buffer (`PendingSlot`, 0.6 s)
  fires in `PlayerTick`; the full tooltip only with Alt.
- Relations: `AArenaCharacter::LocalTeam`; `TeamColor(Team)` in the HUD is relative; `UpdateTeamRing` (a
  `M_ArenaIndicator` ring decal, heroes only).
- Minions: `UArenaMinionAnimInstance` — a native anim instance whose proxy blends an idle and a jog by speed and
  registers "DefaultSlot" itself (`RegisterSlotNodeWithAnimInstance`, `GetSlotWeight`, `SlotEvaluatePose`), so the
  montage-based attacks, reactions and deaths work without an anim blueprint (the pack ships none). Data:
  `meshAlt` (team 1), `idleAnim`, `runAnim`, `runAnimSpeed`, `teamTint` (0: the pack colours).
- Minion aggro: `ArenaBot::Score` for minions (minion 1, hero 0.35, aggressor 4); `MinionAggroUntil` set on hero→hero damage.
- Rendering: D3D12 with **both SM5 and SM6** cooked. In UE 5.8 Lumen on D3D requires SM6 (`DoesPlatformSupportLumenGI`;
  on SM5 it silently fell back to DFAO), but SM6 alone cost ~30 % of the frame rate at High; so the game starts on
  SM5 (`DefaultGameUserSettings.ini [D3DRHIPreference] PreferredFeatureLevel=sm5`) and `FArenaSettings::SyncShaderModel`
  writes sm6 only for Epic ("Epic · Lumen", effective at the next start). Scalability (`DefaultScalability.ini`):
  Epic = software Lumen GI + reflections from mesh distance fields, trimmed; High = no Lumen; CSM + distance-field shadows past 90 m; contact shadows; volumetric fog (High/Epic);
  post: histogram exposure EV100 1–3.5, local exposure, slight saturation / contrast; small scatter meshes out of the
  distance fields and Lumen, WPO off past 30 / 60 m. Minimap capture: no dynamic shadows, exposure calibrated from a
  read-back of the capture (mean ≈ 0.44).
- Measurement: `-ArenaCmdAt=<s>:<cmd>|...` (e.g. `profilegpu`).

## ADR-11 Network foundation (2026-09-28, v12)
- Multiplayer is a goal (operator). `AArenaGameState` (replicated) carries the phase, the clock, the score, one
  `FArenaHeroStat` per hero (level, K/D/A, minion kills, gold, damage to heroes, damage taken, healing, items, alive,
  respawn time) and the kill feed. The game mode (server only) stays the authority and writes it every frame
  (`SyncGameState`); the HUD's top bar, scoreboard, kill feed and end screen read only the game state.
- Next steps: every new system is built server-authoritative and replicated (v14 structures, jungle, boss; v15
  draft); v16: client input and ability activation through the server, replicated projectiles / areas / effects,
  host and join by IP.
- Current state for the record (review 2026-09-28): the rest of the HUD, the shop and the abilities still reach the
  game mode directly, abilities run on local timers, and the GAS attributes are written directly (no Gameplay
  Effects). The v1 module map above is historical.

## ADR-12 Conquest rules as pure functions (2026-09-28, v14)
- `Core/ArenaConquestRules.h` (namespace `ArenaConquest`): the protection chain (`IsVulnerable`: a structure opens
  when every lower tier of its lane is down, the core when any inhibitor is down — works for one or two towers a
  lane), tower target choice (call for help → current → minions → heroes), the shot ramp, the minion share, heroes
  on structures (basic attacks within reach, the backdoor cut), the monster level and the timeout winner. Covered by
  `Arena.Conquest`; the game mode only feeds them state.
- Structures and camps are `AArenaCharacter`s (StructureKind / team 2 monsters) so damage, death, replication and
  the HUD need no second code path; a structure is a dynamic navmesh obstacle. The layout waits for the navmesh
  (bases and lane middles project, no build in progress, 20 s safety) before placing anything.

## ADR-13 LAN multiplayer: listen server, replicated definitions, a client mirror (2026-09-28, v16)
- Topology: a listen server (the host plays) is the only authority; clients join by IP (`open <ip>`), port 7777.
  No online subsystem, no dedicated server (LAN is the scope the operator set).
- A unit replicates *which definition it was built from* (`FArenaNetSetup`: kind, index, team, level, skin, lane,
  tier) and each client builds the same body from the same data (`OnRep_Setup` → `InitCharacter`). Vitals go to
  everyone (`FArenaNetVitals`); gold, ranks, cooldowns, items and potions only to the owner (`FArenaNetOwner`,
  COND_OwnerOnly), written at 10 Hz.
- Events are multicasts (cast with the animation variant, hit, death with the chosen death animation, status,
  spawn); the client draws the shots and areas as visual-only actors (no damage). Voices are client calls.
- Client → server: server RPCs from the player controller (pick, cast with the aim, rank, buy/sell/potions,
  recall, revive, ping), a cast throttled per slot (0.15 s). Movement is the engine's character movement
  (autonomous proxy, server-corrected).
- The HUD and menus were written against the game mode. On a client an `AArenaClientMirror` (a game-mode
  subclass that spawns no game state) is filled every frame from the replicated `AArenaGameState`, with the
  server clock converted to local time; `AArenaGameMode::Get()` returns the authority's or the mirror.
- Joining: teams alternate; a late guest takes over a bot's hero, a leaving guest hands it back to a bot.
- Evidence: `-ArenaNetHost` + `-ArenaNetGuest` on one machine (QA 17).

## ADR-14 Heroes face where they run; balance measured by duels on neutral ground (2026-09-29, v17)
- The Paragon anim blueprints shipped with the packs play a forward jog only (their Ground Locomotion "Run" state is
  `JogFwdSlopeLean`, leaning by `YawDelta`; the directional `Locomotion_BS` is unused) and cast the pawn to their
  own `*PlayerCharacter` blueprints for combos only. Dumped by `-ArenaLocoLab -ArenaDumpAnimBP=<path>` (every graph,
  node, pin and link). A hero that faced the camera and strafed slid the forward jog sideways and backwards.
- So every hero (the player's and the bots') turns to where it runs (`bOrientRotationToMovement`, 720 °/s: the
  pack's lean into the turn works), and a cast turns it to its aim at 1080 °/s for the cast (`FaceAim`, also on a
  LAN guest's copy from the cast multicast); the pack's aim offset (`Yaw`/`Pitch` from the base aim rotation)
  turns the head and chest towards the camera in between. The hit itself always goes along the aim. The camera
  follows the controller (spring arm `bUsePawnControlRotation`). `arena.FaceMovement 0` restores the old strafe.
- Balance evidence: `-ArenaDuelLab` (every melee hero against every ranged one, hard bots without their stat edge,
  level 9, 15 m apart, twice with the sides swapped) plus `Arena.Balance` (VR-07 time to kill by role, the kite
  model). The duel ground is base B's flat plateau with both bases moved far off once the navmesh is up — inside a
  base the ranged side took the spot for the enemy fountain and only backed away, and the melee side counted as
  "safe" and was never shot (every duel up to r12 was skewed).
